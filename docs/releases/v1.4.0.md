# Release v1.4.0

## Summary

This release hardens the repository narrative around governance, CI, and SQL portability. The objective is not to add surface area for its own sake, but to make the existing operational model easier to trust and easier to review.

## What Changed

- added `docs/governance_framework.md` to define source-of-truth rules, change classes, and evidence expectations
- added `docs/ci_cd.md` to explain CI job boundaries and local-to-CI parity
- updated root and localized READMEs so governance and automation expectations are visible from the first read
- updated merge, release, and contribution docs so repository-policy changes require explicit validation
- aligned `sql/create_tables.sql` with the dimensional DDL and made the churn watchlist example SQLite-portable
- exposed a dedicated `make governance` target and separate governance job in CI

## Why It Matters

- reviewers can now see how code, docs, SQL, and CI are expected to move together
- SQL examples better reflect the actual local-first warehouse strategy
- governance regressions are easier to isolate because policy validation is its own CI surface

## Reviewer Reading Order

1. `README.md`
2. `docs/governance_framework.md`
3. `docs/ci_cd.md`
4. `.github/workflows/ci.yml`
5. `sql/README.md`
