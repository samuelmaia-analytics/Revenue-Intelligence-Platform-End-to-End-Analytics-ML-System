# Release v1.4.0

## What Changed

- formalized processed artifact versioning and compatibility policy
- added rollback-oriented regression coverage for processed contracts
- introduced optional Postgres CI smoke support when repository secrets are available
- added schema-prefixed Postgres smoke support for warehouse validation
- strengthened processed artifact validation with value-level quality rules
- documented larger synthetic benchmark trend and artifact storage decision
- expanded incident playbooks for model registry and artifact failures

## Why It Matters

This release reduces the gap between "portfolio-quality documentation" and "maintainable operated system".

The repository now makes these engineering signals more explicit:

- governed processed outputs with versioning discipline
- rollback-conscious validation for downstream compatibility
- a realistic migration path from SQLite to Postgres without parallel orchestration
- more credible operational guidance for model and artifact incidents

## Reviewer Focus

Review these files first:

- `docs/processed_contracts.md`
- `src/artifact_validation.py`
- `tests/test_processed_contracts.py`
- `.github/workflows/ci.yml`
- `scripts/smoke_postgres_optional.py`

## Contract and Runtime Deltas

- `pipeline_manifest.json` now records `warehouse_schema` in addition to `warehouse_target`
- processed artifact validation now enforces selected numeric and relationship constraints
- optional Postgres validation can target a schema prefix when provided

## Trade-off

The repository still defaults to SQLite for local reproducibility. Postgres remains optional by design so the project does not force infrastructure complexity just to look more "production-like".
